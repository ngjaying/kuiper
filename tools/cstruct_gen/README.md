# cstruct_gen

`cstruct_gen` is a CLI tool that automatically generates JSON schemas describing the C ABI memory layout of structs for eKuiper's GBF payload decoder.

The tool parses C/C++ header files, cross-references them against CSV service inventories, perfectly computes padding and alignment according to 64-bit ARM ABI rules, and produces the flat `StructDef` format required by the `schema/abi` Go decoder.

## Why is it needed?

When DDS services broadcast data, the `.bin` payloads are often bare C-structs dumped straight from memory. To decode these byte streams, eKuiper needs to know exactly where every field is located. Because C compilers insert invisible padding bytes to align fields in memory, finding absolute byte offsets is complex.

`cstruct_gen` automates this by doing exactly what the C compiler does: computing field sizes, finding the maximum memory alignment, inserting `<pad>` fields between unaligned attributes, and exporting the layout to JSON.

## Usage

```bash
go run . \
  -csv <path_to_all.csv>,<path_to_all2.csv> \
  -hdir <directory_containing_h_files> \
  [-summary <optional_123_summary_for_validation.json>] \
  [-out <output_schema.json>] \
  [--validate]
```

### Required Flags
* `-csv`: Comma-separated paths to CSV files (like `all.csv` and `all2.csv`) that define the "Target Scope". The tool will **only** emit schema definitions for `Service.MethodName` pairs found in these CSVs.
* `-hdir`: Path to the directory containing the C header files (`.h`). The tool scans this directory (non-recursively) to extract struct definitions and variable declarations. It maps a `Service.Method` to its C type by searching for a variable named `{Service}_{Method}` in the headers.

### Optional Flags
* `-summary`: An optional validation JSON file (like `123_summary.json`). If provided, the tool verifies that its generated computed size perfectly matches the expected `declared_size` for every struct.
* `--validate`: If used with `-summary`, causes the tool to exit `1` if any struct fails size verification.
* `-out`: Output JSON file path. Defaults to `abi_schema.json`.

## Mapping Logic & Rules

### Key Generation
Root keys in the generated JSON use the canonical `Service.Method` format (e.g., `Basc_ACChrgMntr.Ntf_ACChrgMntrInfo`). There is **no** `_Proxy` suffix.

### Output Formats

| C Source Type | Generated JSON Schema | Notes |
| :--- | :--- | :--- |
| **Structs** (`typedef struct`) | Multi-field JSON | Consecutive `<pad>` entries generated by the layout engine are safely flattened and merged into consecutive `uint8[N]` chunks. |
| **Primitives** (`uint32_t`) | `{"name":"value","type":"uint32"}` | Bare primitives sent over the wire are wrapped into single-field structs to satisfy the GBF decoder API. |
| **Strings** (`char*`) | `{"name":"value","type":"string"}` | |
| **C Arrays** (`T[N]`) | `{"name":"...","type":"uint8[N*sizeof(T)]"}` | Fixed-size array fields inside structs are flattened to raw bytes. |
| **DDS Sequences** (`dds_sequence_T`) | `{"name":"fieldName","type":"dds_sequence_bytes"}` | Utilizes an offset "Pointer Swizzling" architecture. A 24-byte footprint resolves offset & length metadata to natively slice strings/byte arrays appended to the payload. |

### ARM ABI Alignment Engine

The C Engine evaluates structure memory using standard 64-bit ARM rules, ensuring alignments are structurally capped at **4 bytes**:
* `uint8_t` / `char` / `bool`: Size 1 / Align 1
* `uint16_t`: Size 2 / Align 2
* `uint32_t` / `float` / `enum`: Size 4 / Align 4
* `uint64_t` / `double` / pointers: Size 8 / Align 4 (Capped)
